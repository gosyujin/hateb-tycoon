# 機能の詳細

README「機能」「判定ロジック」および「技術的な注意点」のうち機能の挙動に関する項目を、文言を変えずに移したもの。

## 機能

- **一覧表示**: GitHub Actions(`hotentry-sync.yml`)が定期的に取得・蓄積する `data/hotentry-{category}.json` を同一オリジンから読み込み、カテゴリタブ(総合/一般/世の中/政治と経済/暮らし/学び/テクノロジー/おもしろ/エンタメ/アニメとゲーム、および全カテゴリを統合した仮想カテゴリ「全て」)ごとに一覧表示します。画面をスクロールすると自動で追加の記事が読み込まれます(無限スクロール、追加の通信は発生せず既に取得済みのデータを小出しに表示するだけです)。「全て」はURLで重複排除した上で、他カテゴリと同様に並び替え・検索・ミュートが効きます。
- **並び替え**: 更新日時(はてなの更新日時、デフォルト)/取り込み順(初出日時)/ブックマーク数/タイトルの4種類。カードには「更新 yyyy-MM-dd」としてはてな側の更新日時(JST変換済み)を表示します。
- **検索**: 画面下部に固定したフッターの検索ボックス(最下段。記事ページではその上に前後の記事ナビ・投稿行、さらに上にビルド情報・次回更新の表示が積まれる)で、一覧ページではタイトル・ドメインを、個別記事ページではブックマークしたユーザーid・コメント本文を対象にその場で絞り込みます(結果画面への遷移やEnter操作・補完は無く、入力するたびに即座に絞り込むだけの単純な仕組みです)。画面遷移のたびにリセットされます。
- **幅ごとのレイアウト**(`js/app.js`が`matchMedia`で要素を付け替える。gyazo-tycoonと同じ考え方): 〜640pxは上記のまま(検索欄・前後ナビ・投稿行を下部に固定)。641px〜は前後ナビ(前の記事へ・一覧へ戻る・次の記事へ)を記事ページ本文の末尾に置き固定しない(固定は検索欄+投稿行の2行)。900px〜はさらに検索欄をヘッダーへ移し、下部に固定するのは投稿行のみ(投稿行が無い画面ではフッターに何も残らない)。
- **URL直接入力**: 一覧ページ・個別記事ページの検索ボックスに`http(s)://`で始まるURLを入力してEnterを押すと、一覧に載っていない記事でも`#/entry?url=...`へ遷移してそのURLのブックマークコメントを表示します(表示は通常の個別記事ページと同じ。一覧に無いURLなので前後の記事ボタンは無効)。個別記事ページからも同様に別のURLへ遷移できます。IME変換確定のEnterでは遷移しません。
- **コメント表示**: 一覧の「ブックマークコメントを見る」から個別記事に遷移すると、`https://b.hatena.ne.jp/entry/jsonlite/?url=...` をJSONPで取得し、そのページをブックマークした各ユーザーのコメント・タグ・日時を表示します。表示形式は「plain」(テキスト中心)と「rich」(ユーザーアイコン・タグ付き)を切り替え可能で、選択状態は`localStorage`に保存されます。
- **description(記事の概要)の本文差し替え**: 一覧データの`description`は、はてなのRSSの概要(平均150字、空のものもある)ではなく、記事のページから取った本文の抜粋(300字)に差し替える(`scripts/article_body.py`。取得はGitHub Actionsで、新しい記事から1回40件ずつ。取れない・元より長くならない記事はRSSのまま)。`descriptionSource: "body"`が差し替え済みの印。ミュートの「コメント」フィルタも本文で判定するので、本文に当たる語でも記事が消える。ストリーム表示では、概要は初期状態で全文を出し(**スマホ幅=640px以下だけは最初から3行に畳んだ状態**で、記事ページの概要も同じ。表示時点で判定する)、押して3行に畳める(畳める目印として下に「▲ 閉じる」/「▼ 続きを読む」を出す。**概要が3行以内でも出す**=見え方を揃えるためで、短い概要は畳んでも見た目は変わらず、ラベルが替わるだけ)。概要が無い記事は、同じ位置に「記事が取得できませんでした(理由)」を出す(理由は一覧データの`bodyReason`のコードを`js/app.js`の`BODY_REASON_LABEL`で表示名にする。例: `http-403`→「HTTP 403 アクセスを拒否されました」、`robots-disallow`、`hatena-bookmark-page`。まだ取りに行っていない記事は「まだ取得していません」、理由を記録する前にskipにした記事は「理由は記録されていません」(次の実行で1回だけ取り直して理由を残す))。記事ページ(`#/entry`)の概要(タイトル下の引用)も同じ扱いで、本文を取れなかった記事はRSS由来の概要がそのまま出る。一覧を経由せずURLを直接開いた時は、一覧データが無いので概要は出ない(理由も出さない)。robots.txt遵守などの決まりと経緯は[decisions/article-body-description.md](decisions/article-body-description.md)。
- **ストリーム表示(`#/stream`)**: ヘッダーの📡から開く、かつてのTwitterのStreamのように記事が次々とページ上部へ追加されていく画面(記事もコメントも新しいものが上=降順)(`js/stream.js`)。データ元は一覧と同じ`data/hotentry-*.json`(カテゴリーは直前に見ていたもの。`?cat=`でも指定可)で、フィルタ(ミュート)に掛からない記事だけを出す。開いた時点の一覧のうち新しい側30件を古い順に、設定した間隔(自動/1/3/5/10/30秒、1/3/5分。localStorageに保存、デフォルト3秒)でひとつずつ先頭に追加し、それ以前の記事は「既出」として流さない。2分ごとに一覧を再取得し、URLが既出でない記事だけを待ち行列に足す(データは15分おき更新なので、新着が出るのはその周期)。待機中にミュートされた記事は流さない。先頭付近(スクロール160px未満)を見ている間は先頭に張り付いて新着を見せ(DOMは150件まで、古い=下の方から間引く)、下へ読み進めている間は、追加で押し下げられた分だけスクロール位置を自前で補正して読んでいる場所を動かさない(Safariにscroll anchoringが無いため`.stream-list`は`overflow-anchor: none`にして二重に補正しない。補正するかは「挿入位置が画面の上端より上か」で決め、中身が空のコメント欄は`display:none`で位置が取れないので、直前のタイトル・概要の下端で判定する)。一時停止ボタンあり。**前回の続きから表示する**: 表示中の記事(新しい側60件)・各記事のコメント(15件まで)・既出URLをカテゴリーごとに`localStorage`(`hateb-tycoon:streamState:<category>`、約100KB)へ保存し(流すたび・コメントが増えるたびに1秒まとめ、裏に回る時・離れる時・`pagehide`)、リロードや開き直しの時は取得を待たずにまず並べ直す(オフラインでも前回分は見られる)。3日以上前の保存は使わずいちから流す。待機中だった記事は「既出」に含めないので、続きから流れる。保存後にミュートされた記事は出さない。コメントは「これより古いものは省略済み」の境目(`floor`)を覚え、省略した古い分が後から湧かないようにする。保存に失敗(容量超過等)しても、いちから流すだけで動作は変わらない。**表示している間は画面をスリープさせない**(Screen Wake Lock。裏に回ると自動で解放されるので、前面に戻った時に取り直す。非対応・拒否された環境では何もしない)。**「自動」の間隔**は、次回のデータ更新の目安時刻(`data/meta.json`の`nextEstimate`。JSTの`HH:MM`で日付は持たないため今日のその時刻とし、半日以上前になる時だけ翌日扱い)までの残り時間を待機件数で割った値にする(1秒〜5分に丸める。1件流すたびに待機が減るので計算し直す)。目安を過ぎている・取れない時は、最低60秒/10分で割る。目安は大まかなもの(`fetch_hotentry.py`が「実行時刻+15分」を書く。実際のデータ更新はローカルからのdispatchで15分おき前後だが、Macが止まっている間はcronの30分間隔になり、その間は目安を過ぎて「更新待ち」の扱い=最低60秒で割る)なので、正確さは求めない。待機が空の間は5秒ごとに新着が入っていないかを見る(手動の間隔でも同じ)。状態表示には、間隔の選択に関係なく「次まで N秒」(次の記事を1件流すまでの残り秒数。1秒ごとに進む。データ更新までの秒数ではない)を出す。一時停止中は「一時停止中」、待機が空の間は「新着待ち」にし、自動の時は計算した間隔も「(57秒間隔で更新)」「(5分間隔で更新)」と添える。操作行(戻る・一時停止・間隔・状態表示)は全幅で1行に並べ(`.stream-bar`)、状態表示は「表示N / 待機N / 次まで N秒 (自動時の間隔)」と短くして(手動の間隔は選択欄に出ているので繰り返さない)、はみ出す分は省略記号(全文はtitle)にする。641px以上では記事の右にサムネイルを出すが、640px以下では出さない(右の列が本文・コメントの幅を削るため。lazy読み込みのため画像の通信もしない)。480px以下ではボタンを「←」「⏸️/▶️」の絵文字だけにし、状態表示も「表示N」を省いて「次まで」を「次」にし、文字を小さく・余白を詰めて幅を確保する(375pxで1行に収まるのを確認)(`aria-label`は残す)。タブが裏にある間は追加を止め、前面に戻ると再開して再取得する。×(URLをミュート)・ドメインボタン(ミュート設定を開く)・「N users →」(記事ページへ)は一覧と同じ。各記事の下には、コメント付きのブックマークだけを新しい順に出す(記事を追加した時にjsonliteで取得。初回は新しい側10件までで、それ以前は一番下に「他N件のコメント」とだけ出す)。以降は3分ごとに、表示中の記事のうち新しい側20件を取り直し(JSONPを連打しないよう300ms空けて順に)、新しく付いたコメント(ユーザー+日時で既出判定)だけをその記事のコメント欄の先頭に足す。コメントはコメントビューと同じ判定でミュート(title/domain/user/comment)し、ユーザー名を押すとミュート設定を開く。一時停止中・タブが裏の間は取り直さない。先頭(=最新)の記事だけ背景を淡い青(`--color-latest-bg`)にする(`.stream-list > .stream-item:first-child`)。既読管理(グレーアウト・更新バッジ)・検索・並び替えは対象外。
- **自分のブックマーク(`#/me`)**: 記事ページ下部のバーの🔖から開く、特定のはてなユーザー1人のブックマーク一覧。はてなのAPIはブラウザから直接読めないため、自前の中継Worker(`worker/hateb-proxy.js`、経緯は[decisions/my-bookmarks-worker-proxy.md](decisions/my-bookmarks-worker-proxy.md))経由で取得し、**取得対象のidはWorkerのsecretにだけ置く**(リポジトリ・公開サイト・アプリのlocalStorage・通信のどこにも出ない)。接続設定(Worker URLとアクセストークン)は記事ページ下部のバーの⚙で開く「ブクマ連携の設定」モーダル(未設定時は`#/me`の「接続設定を開く」からも開ける)で入力し、この端末のlocalStorageにのみ保存する(Gist同期の対象外)。入力欄の横の「↗」は、Worker URLが`*.workers.dev`ならその先頭ラベル(Worker名)から組んだCloudflareダッシュボードのWorker画面(`?to=/:account/workers/services/view/<名前>/production`。アカウントIDは持たない。Worker URL自体を開いても`unauthorized`が返るだけなので開かない)、取れない時(未入力・独自ドメイン)はWorkers & Pagesへ(http/https以外は弾く)。Worker設定済みの時だけ「はてな ↗」(`https://www.hatena.ne.jp/oauth/develop`。ログイン済みなら自分のOAuthアプリ画面へ飛ぶので、**はてなidを含むURLは作らない**)も出す。表示はコメントビューと同じplain/rich(`commentLayout`を共有。richは記事サムネイル付き)で、1件につき日時・ドメイン・タイトル(元記事へ)・「N users →」(`#/entry`へ。`from=me`付きで、戻るボタンは`#/me`へ戻る)・コメント・タグを出す。ミュートは一覧・コメントと同じ判定(title/domain/url/comment)を取得済みの全件に適用し、×ボタン(URLをミュート)・ドメインボタン(ミュート設定を開く)・選択文字クイックフィルタが使える。検索欄はタイトル・ドメイン・コメント・タグを絞り込む(URLを入れてEnterで記事ページへ遷移するのは従来通り)。richの時だけ、コメント付きのブックマークのスター数をコメントの末尾に「⭐️n」で出す(コメントビューと同じ表示。0件は何も出さない。plainのままなら通信しない)。取得は`POST /stars`で、はてなのスターAPIのURIにはidが入るため**Workerが組む**(ブラウザは記事の`eid`(一覧APIの`location_id`)と日時だけ渡し、件数だけ返る=idが外に出ない)。50件ずつ、一度取った分は取り直さず、失敗は黙って無視する。20件ずつ無限スクロールで取得し、検索中・失敗後は自動継ぎ足しせず「続きを読み込む」ボタンにする。取得済みの内容は5分間は再取得せず(記事ページから戻った時はスクロール位置も復元)、取得に失敗した時は最後に成功した1ページ目を表示する。
- **ブックマーク投稿(記事ページ)**: 画面下部の「前の記事へ・一覧へ戻る・次の記事へ」の行の上に、「コメント入力欄・🔖(自分のブックマークへ)・⚙(ブクマ連携の設定)・B!ボタン」を1行で出す(ユーザー登録が前提の機能をここに集約。タグ入力欄は無し。エラーがある時だけ1行のメッセージが出る)。Worker未設定でもバーは出し(⚙から設定するため)、入力欄とB!は止めて入力欄に「⚙で中継Workerを設定」と出す。はてなのPOSTは既存を上書き(コメントもタグも)するため、記事を開いたらWorker経由で自分の既存ブックマークを取得して入力欄に入れ(前後の記事へ素早く移る時にWorkerを連打しないよう400ms待つ)、**取得できるまで「B!」は押せず、取得できなかった時も送信させない**。タグは編集できないが、**既存のタグは取得して保持し、そのまま送り直す**(送らないとコメントの更新でタグが消える)。一覧のアカウントとOAuthのアカウントが違う場合はWorkerが409で拒否し、送信不可になる(設定の「保存して接続確認」にも警告が出る)。コメント欄でEnter(スマホのリターンキー)を押すと、キーボードを畳んで投稿する(「B!」ボタンと同じ。ボタンが押せない間は畳むだけ。IMEの変換確定のEnterは何もしない)。送信に成功したら「ブクマしました。」と出し、入力欄には保存された内容が残る(記事ページは再読み込みしない。投稿直後は、はてなのコメント一覧(jsonlite)に自分のコメントがまだ反映されないことがあり、再読み込みしても出なかったため)。「自分のブックマーク」ページは次に開いた時に取り直す。OAuth 1.0aの署名はWorker側(アプリにはコンシューマ/アクセストークンのシークレットが無い)。経緯・導入手順・未検証は[decisions/bookmark-post-via-worker.md](decisions/bookmark-post-via-worker.md)。
- **コメントのスター数(richのみ)**: 個別記事ページをrichレイアウトで表示している時だけ、はてなスターAPI(`https://s.hatena.ne.jp/entries.json`)で各コメントのスター数を取得し、コメント末尾に「⭐️n」と表示します(0件は何も表示しない。誰が付けたかは扱わず数のみ。通常のスター+色付きスターの合計で、多い場合にAPIが`{count: N}`にまとめた分も加算)。対象はコメント付きで表示中のブックマークのみで、ブックマークのパーマリンク(`https://b.hatena.ne.jp/{user}/{yyyymmdd}#bookmark-{eid}`)をURIとして50件ずつまとめて問い合わせるため、リクエストは**記事を1回開くごとに ceil(コメント数/50) 本**(ほとんどの記事は1本、並列実行、10秒タイムアウト)。取得は記事ごとに1回だけで、plain→richに切り替えた時に初めて走り、plainのままなら一切通信しません。失敗しても黙って無視し、コメント表示には影響しません。単数形の`entry.json`はCORSヘッダが無く、`callback`によるJSONPも効かないため使えません(`entries.json`のみCORS対応)。
- **コメント一覧非表示設定の検出**: はてな側で「コメント一覧は非表示に設定されています」になっている記事は、jsonliteが「ブックマーク数はあるのに`bookmarks`が空」で返す(コメントが無いだけの記事では`bookmarks`は空にならない。25記事で実測確認)。この形を検出した場合は「コメントはありません。」ではなく「コメント一覧は非表示に設定されています。」と表示し、その時点でミュートに自動登録して一覧から外します。この設定はブログ/ユーザー単位でかかるため、ユーザー単位だと分かっているホスト(はてなブログ系のサブドメイン、`zenn.dev/{ユーザー}/`・`speakerdeck.com/{ユーザー}/`)は`urlprefix`(URL前方一致)でまとめて登録し、それ以外のホストはホスト全体を巻き込まないよう従来どおりその記事のURL(url)のみ登録します(許可リストは`js/filters.js`の`scopeRuleForUrl`。コード内の初期値に加え、フィルタ用Gistに`tycoon-scope-hosts.csv`(`mode,host`。`mode`は`path`=`zenn.dev`型 / `subdomain`=`hatenablog.com`型)を置くとホストを追加できる(「Gistを作成」時に`path,zenn.dev` / `path,note.com` / `subdomain,hatenablog.com`の初期内容で自動作成する)。Gist側を直接編集する取り込み専用で、起動時と「保存して同期」で取り込んでlocalStorageにキャッシュし、書き戻さない。不正な行は無視)。同じ判定は、一覧・個別記事ページのドメインボタンを押してミュート設定を開く時にも使い、該当ホストはドメイン全体ではなくユーザー単位の`urlprefix`が入力済みで開く(Gist同期は積み上げ方式のため、他端末にも広がり、削除は同期されません)。
- **未ブックマークのURL**: まだ誰もブックマークしていないURLは、jsonliteがエラーではなく`null`を返す。コメント内のリンク化やURL直接入力で普通に起こるため、例外にせず「このURLはまだ誰もブックマークしていません」と元記事へのリンクだけを表示する(既読記録・オフライン用キャッシュ保存の対象外)。以前は`normalizeEntryInfo`が`null`の`raw.url`を読んで「null is not an object (evaluating 'raw.url')」になっていた。
- **コメント中のURLのリンク化**: コメント本文に含まれる`http(s)://`のURLは、hateb-tycoonの個別記事ページ(`#/entry?url=...`)へのリンクになります(plain/rich共通、同じタブで遷移)。URL以外の部分は従来どおりエスケープして出力します。URL末尾の句読点・括弧は含めず(「(https://example.com)」のように括弧で囲まれていても巻き込みません。`Foo_(bar)`のようにURL内で括弧が対になっている場合は含めます)、長いURLがスマホ幅ではみ出さないよう折り返します。
- **既読管理**: 一度開いた記事は視覚的に既読(輝度低下)として扱われます。ブックマーク数が既読時から一定以上増えた場合(設定で割合/件数を指定可能)は、グレーアウトを外して未読同様に目立たせつつ、「更新」バッジを付けて、既読済みでブックマーク数が増えたことを示します(未訪問の未読とは見分けが付きます)。文言は当初「既読」でしたが、バッジとして強調されていると意味が分かりにくかったため「更新」に変えました(本当は「更新あり」が分かりやすいが、スペースの都合で「更新」)。バッジの位置は、richでは「更新 yyyy-MM-dd」(はてなの更新日時)の左です。plainではタイトルの左に置くと開始位置がずれて実機で使いにくかったため、行の流れの外に出し(横幅も改行も増えず、タイトルの開始位置が揃う)、行の左端のアクセント線(Scrapboxのテロメア風)だけで示します(未読・既読の行も同じ3pxを透明で確保し、見た目の位置を揃えています)(左上角に「更新」タブも付けてみましたが、スマホ幅でごちゃついたため線のみにしました)。plainでは、タイトルと「N users →」を合わせた範囲全体がブックマークページへのリンクになります(元記事へはカード/行内のタイトルをTab操作で、またはブックマークページ内のタイトルから開けます)。「既読なら非表示」トグルで一覧から隠れるのは、更新の無い既読記事のみです(このバッジ付きの記事は隠れません)。
- **新着コメント表示**: 個別記事ページを開くと、前回そのページを開いた時刻より後に付いたコメントに「NEW」バッジを付け(一覧の「更新」と同様、グレーアウトはしません)、前回訪問時点で既にあったコメントはグレーアウトし、ステータス行に新着件数を表示します(plain/rich共通)。判定はコメントのtimestamp(JST、分単位)と`visited`に記録済みの前回訪問時刻の比較のみで、コメント一覧自体は保存しません。timestampが分単位のため、前回訪問と同じ分のコメントは新着側に倒します。初訪問の記事は比較対象が無いためバッジは付きません。開いた時点で訪問時刻が更新されるため、同じ記事を続けて開き直すとバッジは消えます。
- **キーボード操作**: 一覧ページで矢印キーを押すと最初の未読記事へジャンプ、個別記事ページでは前後の記事へ移動します。移動先は「既読かつ更新なし」の記事を読み飛ばして決め(先読みの対象も同じ)、その判定は一覧から記事ページに入った直後の既読状態(スナップショット)を一覧に戻るまで使い回します(毎回判定し直すと、見てきたばかりの記事まで「前の記事へ」で飛ばしてしまうため。滞在中に隣の記事が更新された場合は考慮しません)。**オフライン時(`navigator.onLine`が偽)は読み飛ばしの条件が変わり**、既読の読み飛ばしをやめて、コメントをキャッシュ済み(`localStorage`の`entryCache`)の記事だけを辿ります(既読で飛ばすと、事前取得した記事を大きく飛び越えて「コメントを取得できませんでした」の記事ばかりになるため)。機内モード(`navigator.onLine`)に加え、電波が弱いだけで`onLine`が真のままの場合も、記事の取得がキャッシュ頼みになる/失敗した時点で実質オフラインとみなし(取得に成功するか`online`イベントまで継続)、同じ仕様に切り替えます。切り替わっている間は、下部ナビの上に「オフラインのため/電波が弱いため、コメント取得済みの記事だけを前後に移動します」と案内を出します。ただしこのセッション中に既に開いた記事は、元が既読でも飛ばしません(ページ下部の「前の記事へ」「次の記事へ」ボタンでも同様の操作が可能。スマホでの片手操作を想定した全幅ボタンです)。
- **既読の同期(Gist)**: 設定モーダルの「既読の同期」で、既読をシークレットGist(`hateb-tycoon-visited.json`)経由で端末間共有できます(既読のみ。フィルタ設定は対象外)。`localStorage`が常に正で、既読の記録・判定はGistに触れません。通信は起動時/タブ復帰時(前回から5分以上)の読み込み(ETagで304なら実質ゼロコスト)と、既読が増えた45秒後(またはタブを隠す時)のまとめ書き込みのみです。書き込みにはclassic PATの`gist`スコープが必要(fine-grained PATはGist非対応)で、トークン未設定の端末は読み取り専用になります。トークンは既読の同期とフィルタの同期で共通の専用入力欄(「GitHubトークン(Gist用)」)から設定し、端末の`localStorage`に保存されます(旧仕様で既読同期の設定に入っていたトークンは自動で引き継ぎ)。Gist IDの隣の「↗」で`https://gist.github.com/<id>`を開けます(ユーザー名なしのIDだけでも所有者のGistページへリダイレクトされます)。マージはURLごとに`time`の新しい方を採用します。
- **ミュート機能**: 右上の「フィルタ設定」から、以下3種類のワードリストを追加・削除できます。ワードは `localStorage` に保存され、ブラウザを閉じても保持されます。
  - `mute`(ミュートワード): 該当したら非表示。ただし `unmute` に該当すれば例外的に表示。
  - `unmute`(ミュート解除ワード): `mute` の例外として表示を維持する。
  - `forceMute`(強制ミュートワード): 該当したら `unmute` の設定に関係なく必ず非表示。
  - 各ワードは「タイトル」「ドメイン」「はてなユーザー」「ブックマークコメント」「URL」のいずれかを対象に判定します。URL以外は部分一致(大文字小文字を区別しない)、**URLのみ完全一致**です(記事カードの「×」ボタンで、その1記事だけをピンポイントでミュートする用途のため)。一覧表示のデータには個々のブックマークユーザー・コメント情報が含まれないため、「はてなユーザー」「ブックマークコメント」によるミュートは個別記事のコメント表示(jsonlite由来)でのみ有効です。ただし「ブックマークコメント」は、一覧のRSS由来の記事概要(`description`)にも一致判定を行い、一致した記事は一覧から消え、個別記事ページでも「このエントリーはフィルタ条件により非表示になっています。」を表示します(個別記事ページは一覧取得済みの`description`がある時のみ判定。URL直接入力などで一覧データが無い場合は判定しません)。
  - フィルタ設定はCSV(`type,value`)でエクスポート/インポート可能です(ファイルダウンロード・クリップボードコピー・画面上へのテキスト表示の3通り。インポートはCSVファイル選択)。
    - **フィルタのGist同期**: 既読の同期と同じ仕様で、Gist IDだけを設定します(トークンは共通)。ミュート・ミュート解除・強制ミュートの**3種をまとめて1つのシークレットGist**に、種類ごとのCSV(`tycoon-filter-<mute|unmute|forceMute>.csv`(feed-tycoonと共有するためアプリ名は含めない))として保存します。「Gistを作成」でGistとファイルを自動作成し、「保存して同期」は「Gistから取り込み(マージ)→ローカルとの和集合でGistを上書き」です。つまりルールは**積み上げ方式**で、削除は同期されません。消したい場合はGist側のCSVを直接編集します(他端末のローカルに残っていれば次の同期で復活します)。トークン未設定の端末は取り込みのみ(読み取り専用)です。
      - リモートのCSVが1行でも不正(値が空など)な種類は、取り込まず、ローカルの内容での上書きもしません(手編集の途中で壊したCSVを消さないため)。その旨は取り込み結果に表示されます。ヘッダーのみ・空のファイルは「ルール無し」として扱います。
      - [feed-tycoon](https://github.com/gosyujin/feed-tycoon)と同じGist・同じファイルを共有できます。hateb-tycoonが持たない`type`(`source`/`tag`/`description`等)の行は取り込み時にエラーにせず無視し(結果に「未対応の種別N件は無視」と表示)、上書き時にはリモートの行をそのまま残します(feed-tycoonのルールを消さないため)。`type`が空・`value`が空・列数不正の行はエラーです。
    - **起動時の自動取り込み**: Gist IDを設定済みなら、アプリ起動時にGistから取り込みます(書き込みはしません。ETagで変更なしなら304)。記事ページは既読判定のため最初の描画前に最大3秒待ちますが、一覧ページは待たずに先に描画し、取り込みでフィルタが変わった時だけ絞り直します(失敗は無視して通常起動)。
    - 旧仕様の「インポート用URL」(Gist rawURLを種類ごとに登録)は廃止しました。
- **オフライン対応(機内モード等)**: Service Workerによりアプリ本体と全カテゴリーの一覧データを事前キャッシュし、電波が無い状態でも一覧・既読管理・フィルタ設定は利用可能です。詳細は[architecture.md](architecture.md)の「オフライン対応の仕組み」を参照してください。

## 判定ロジック(ミュートワード、優先順位)

1. forceMute に一致する -> 非表示(確定)
2. mute に一致する
     -> unmute にも一致する -> 表示

## 機能の挙動(旧README「技術的な注意点」より)

- **「全て」タブのデータ**: `scripts/fetch_hotentry.py`が全カテゴリーをurl基準で重複排除した`data/hotentry-everything.json`を同時に生成し、アプリはこの1本だけを取得します(以前は10本取得してブラウザでマージしており、遅い1本に全体が引きずられていた)。ファイルが無い/取れない時は従来のカテゴリー別取得+マージ(`getEverythingEntriesFromCategories`)にフォールバックします。Service Workerの`DATA_FILES`にも含めています。
- **一覧の先出し表示**: `renderListView`は、Cache Storageに前回取得分があればそれを先に描画し(`HatenaAPI.getCachedHotEntries`)、裏でネットワーク取得して内容が変わった時だけ差し替えます(スクロール位置維持)。キャッシュが無い時だけ「読み込み中…」で待ちます。取得失敗時も先出しした一覧は消しません。カテゴリー切替で古い取得結果が上書きしないよう`listRenderSeq`で世代管理しています。
- **一覧の自動リフレッシュ**: 一覧データは静的JSONでサーバーからpushできないため、feed-tycoonと同じく「ページが前面に戻った時(`visibilitychange`)に、最後の読み込みから5分以上経っていれば読み直す」方式にしています(`refreshListIfStale()`)。通常の読み込み(`renderListView`)は一覧を一度空にしますが、自動リフレッシュは**取得に成功し、かつ内容が変わっていた場合のみ**差し替え、スクロール位置も維持します。オフライン復帰などで取得に失敗しても表示中の一覧は消えません。
- **新バージョンの自動検知**: ホーム画面追加のPWAはタスクに残ると起動時のJSがメモリに居続け、画面遷移もハッシュ変更のみでリロードされないため、デプロイ後も古いバージョンのまま動き続けていた(フッターのビルドSHAが古い、新UIが出ない)。`reloadIfNewVersionDeployed()`が前面復帰時(`visibilitychange`、60秒に1回まで)に`js/build-info.js`を`cache: 'no-store'`で取得し、`BUILD_INFO.codeVersion`と違えば`location.reload()`する。比較に`sha`ではなく`codeVersion`(`deploy-pages.yml`が`git log`で求める「アプリ本体(`index.html` `css/` `js/` `service-worker.js`)を最後に変更したコミット」)を使うのは、`sha`が15分おきのデータ更新コミットでも変わり、復帰のたびに再読み込みしてスクロール位置が飛ぶため。同じ`codeVersion`への再読み込みは`sessionStorage`のガードで1セッション1回まで(無限ループ防止)。`codeVersion: 'dev'`(ローカル)では何もしない。フッターにも同じ`codeVersion`とそのコミット日時(JST)を表示する(不具合報告で「フッターに○○と出ている版」と伝えるだけでコードの版が特定できるように。`sha`はデータ更新でも変わるため表示しない)。
- **自動スクロール**: ヘッダーの▶️/⏸️でON/OFF。状態は`localStorage`(`hateb-tycoon:autoScroll`)に保存し、一覧⇔記事・前後の記事へ移動してもONのまま続く。`requestAnimationFrame`で`window`を設定画面で変えられる速度(既定毎秒20px、`hateb-tycoon:autoScrollSpeed`)で下へ送るだけで、wheel/touch/keydownの直後1.5秒は一時停止して手動操作を邪魔しない。設定画面を開いている間も一時停止し(状態は変えず、閉じれば再開)。

## フィルタのGist同期 詳細仕様(旧 docs/gist-sync-spec.md)


hateb-tycoon コミット `ac1f206` で導入した仕様。feed-tycoon も同じ方式へ移行するための引き継ぎ資料。
実装の正本は hateb-tycoon の `js/gist.js` / `js/filter-sync.js` / `js/app.js`(「フィルタの同期」節)。

### 1. 概要

- フィルタルール(hateb-tycoonは mute / unmute / forceMute の3種)を、**シークレットGist**経由で端末間共有する。
- 設定するのは **Gist ID だけ**(GistのURLを貼ってもIDを抽出する)。ルールの保存形式は従来どおりCSV(`type,value`)。
- 既読の同期(hateb-tycoon `js/sync.js`)と同じ操作感・同じトークン。
- **旧仕様(種類ごとにGist rawURLを登録して取り込む)は廃止**。移行処理は入れていない。

### 2. Gistの構成

- 1つのGistに、ルールの「種類(kind)」ごとに1ファイル。ファイル名は `tycoon-filter-<kind>.csv`(**アプリ名を含めない**。プロジェクト間で同じGist・同じファイルを共有する)
  - `tycoon-filter-mute.csv` / `tycoon-filter-unmute.csv` / `tycoon-filter-forceMute.csv`
  - feed-tycoon も**同じファイル名**を使う。kindはhateb-tycoonと同じ3種(mute/unmute/forceMute)を前提とする(feed-tycoon側に他のkindがあれば別途協議)。
- CSV形式: 1行目ヘッダー `type,value`、改行 `\r\n`、`,` `"` 改行を含む値は `"` で囲み `""` でエスケープ。出力は `type asc, value asc` ソート済み。
- 説明(description): `hateb-tycoon filters`。`public: false`(シークレット)。

#### type の扱い(feed-tycoon固有の注意)
- 取り込み時、自アプリが扱わない type の行はエラーにせず無視して件数を数える(結果に「未対応の種別N件は無視」)。
  hateb-tycoon が扱うのは `title`/`domain`/`user`/`comment`/`url`。feed-tycoon は加えて `source`/`tag`/`description` も扱うので、それらは取り込む(逆に feed-tycoon が扱わない type があれば無視)。
- **ファイルを共有するため、上書き時は「リモートCSVにあった未対応typeの行」をそのまま残して書き出す**(相手アプリのルールを消さない)。実装: パーサーが無視した行を `ignoredRules` として返し、push時にローカルルールと合わせてソートして出力する。**feed-tycoon側でも必ず同じ保持処理を入れること**(入れないと hateb-tycoon 専用type の行を上書きで消す)。

### 3. トークン(両同期で共通)

- classic PAT の `gist` スコープ(fine-grained PATはGist非対応)。
- **独立した入力欄**「GitHubトークン(Gist用)」に分離。既読同期・フィルタ同期の両方がこれを使う。
- 保存先: `localStorage['hateb-tycoon:gistToken']`(feed-tycoonは自アプリのキー名にする)。
  - 入力欄の `change` イベントで保存。各「保存して同期」「Gistを作成」ボタンでも押下時に最新値を保存してから処理する。
  - 旧仕様で既読同期の設定(`hateb-tycoon:sync`)内に同居していたトークンは、新キーが未設定の時のみ自動で引き継ぐ(空文字を保存済みなら再移行しない)。
- **読み取りにトークンは不要**(シークレットGistはIDを知っていれば読める)。トークン空の端末は読み取り専用。

### 4. UI

インポート・エクスポート設定セクションの下部に「フィルタの同期(Gist・全種まとめて)」:

1. Gist ID 入力欄(placeholder「Gist ID または URL」)+ 「↗」リンク
2. ボタン: 「保存して同期」「Gistを作成」
3. ステータス行(`filter-sync-status`): 未設定 / 「読み書き|読み取り専用 / 最終同期 <日時> [/ エラー: …]」
4. 結果詳細は既存のインポート結果欄(`import-status`)に表示

- 「↗」: `https://gist.github.com/<ID>`(**アカウント名不要**。IDだけで持ち主のGistページへリダイレクトされる)。IDが空なら非表示。入力欄の `input` イベントでも更新。既読同期側にも同じ「↗」を付けた。
- 種類タブ(「対象: ミュート」)とは**連動しない**。同期は全種まとめて。CSVコピー/エクスポート/ファイルインポートは従来どおり選択中の種類のみ。
- 旧「Gistから取得」URLフォームと「↗」(rawURL用)は削除。

### 5. 動作仕様

#### 「Gistを作成」
1. Gist IDをクリアして設定 → 全kindのローカルCSV(ヘッダーのみでも可)で `POST /gists`(トークン必須、無ければ「先にトークンを入力してください」)。
2. 返ったIDを保存 → 続けて「保存して同期」と同じ処理を実行。

#### 「保存して同期」(`FilterSync.sync`)
1. 入力欄のIDを保存(ETagはクリア)。ID空ならエラー「Gist IDを入力してください」。
2. `GET /gists/<id>`(ETagなしで全量取得)。
3. 各kindについて、リモートCSVを **取り込み(マージ)**:
   - ファイル無し/空/ヘッダーのみ(`type,value`だけ)→ 「リモートにルール無し」(スキップ。※パーサーは空データをエラーにするので先に除外する)
   - 解析エラーが1行でもある → **その種類は取り込まず、上書きもしない**(手編集途中の壊れたCSVをローカルで潰さないため)。エラーは結果に表示。
   - それ以外 → 既存ルールと重複(`type` + `value` の大文字小文字無視一致)しない分だけ追加(`Filters.importRules`)。
4. トークンがあれば **上書き(push)**: 不正CSVでない各kindについて、ローカルルール(ソート済みCSV)とリモートCSVを改行正規化・trimして比較し、**差分のあるファイルだけ** `PATCH /gists/<id>` で更新。
   - ローカル0件かつリモートファイル無し/空のkindは作らない。
   - 差分が無ければPATCHしない。書き込んだ場合はETagをクリア(自分の書き込みでETagが変わるため)。
5. 最終同期時刻を保存。結果表示: 「N件を取り込み、Gistへ Nファイルを書き込み|トークン未設定のため書き込みなし、未対応の種別N件は無視 / 不正なCSVは取り込まず上書きもしていません(kind: エラー…)」
6. 取り込み後はルール一覧と一覧画面を再描画。失敗時は `lastError` を保存して「失敗: <理由>」。

**積み上げ方式**: 同期 = リモートとローカルの和集合。**削除は同期されない**。消したい時はGist側のCSVを直接編集する(ただし他端末のローカルに残っていれば次の同期で復活する)。

#### 起動時(`FilterSync.syncOnStartup`)
- Gist ID設定済みなら、最初の描画前に **取り込みのみ**(書き込みなし)。
- 保存済みETagで `If-None-Match` 付きGET。304なら何もしない(レート制限にも数えられない)。200なら上記マージを実行しETagを保存。
- 待つのは最大3秒(`STARTUP_IMPORT_TIMEOUT_MS`)。失敗・タイムアウトは無視して通常起動(`lastError`は保存、コンソールにwarn)。
- 既読同期の起動時pullと並列実行(`Promise.all`)。記事ページは完了後に初回描画、一覧ページは待たずに描画し完了後にフィルタ件数が変わっていれば再構築。

#### エラー文言(`Gist.describeHttpError`)
401 トークンが無効です(失効の可能性) / 403 アクセス拒否またはレート制限です / 404 Gistが見つかりません(IDまたはトークンの権限を確認)。**401と404**は、トークン設定済みの端末の状態行末尾に「トークンを再発行」リンク(`Gist.TOKEN_ISSUE_URL`=`gist`スコープ入りのclassic PAT作成画面。開くだけで、発行はGitHub上で本人が行う)を付ける(`app.js`の`setGistStatus`。判定は文言一致の`Gist.isTokenError`) / その他 `HTTP <status>`

### 6. モジュール構成(hateb-tycoon)

| ファイル | 役割 |
|---|---|
| `js/gist.js`(新規) | `Gist`: トークン get/set(旧設定からの移行込み)、`parseGistId`、`pageUrl`、`get(id, etag)`(304→null)、`fileText`(truncated時はraw_url取得)、`update`(PATCH)、`create`(POST, public:false)、`describeHttpError` |
| `js/filter-sync.js`(新規) | `FilterSync`: `init({parseCsv,toCsv})`、`sync`、`syncOnStartup`、`createGist`、`configure`、`getConfig`。状態は `localStorage['hateb-tycoon:filterSync']` = `{gistId, etag, lastSyncAt, lastError}` |
| `js/sync.js`(改修) | 既読同期。トークンを `Gist` 共通管理へ移し、API呼び出しも `Gist` 経由に |
| `js/app.js` | CSV解析/生成(`parseImportCsv`/`rulesToCsv`)を `FilterSync.init` に注入、UI配線、起動時同期 |
| `index.html` / `css/style.css` | トークン欄・同期欄のUI、`.gist-row` スタイル |
| `service-worker.js` | `SHELL_FILES` に `js/gist.js` `js/filter-sync.js` を追加(**忘れるとオフライン起動で読み込めない**) |

スクリプト読み込み順: `filters.js` → `visited.js` → `gist.js` → `sync.js` → `filter-sync.js` → … → `app.js`。
