# 機能の詳細

README「機能」「判定ロジック」および「技術的な注意点」のうち機能の挙動に関する項目を、文言を変えずに移したもの。

## 機能

- **一覧表示**: GitHub Actions(`hotentry-sync.yml`)が定期的に取得・蓄積する `data/hotentry-{category}.json` を同一オリジンから読み込み、カテゴリタブ(総合/一般/世の中/政治と経済/暮らし/学び/テクノロジー/おもしろ/エンタメ/アニメとゲーム、および全カテゴリを統合した仮想カテゴリ「全て」)ごとに一覧表示します。画面をスクロールすると自動で追加の記事が読み込まれます(無限スクロール、追加の通信は発生せず既に取得済みのデータを小出しに表示するだけです)。「全て」はURLで重複排除した上で、他カテゴリと同様に並び替え・検索・ミュートが効きます。
- **並び替え**: 更新日時(はてなの更新日時、デフォルト)/取り込み順(初出日時)/ブックマーク数/タイトルの4種類。カードには「更新 yyyy-MM-dd」としてはてな側の更新日時(JST変換済み)を表示します。
- **検索**: ヘッダーの検索ボックスで、一覧ページではタイトル・ドメインを、個別記事ページではブックマークしたユーザーid・コメント本文を対象にその場で絞り込みます(結果画面への遷移やEnter操作・補完は無く、入力するたびに即座に絞り込むだけの単純な仕組みです)。画面遷移のたびにリセットされます。
- **URL直接入力**: 一覧ページ・個別記事ページの検索ボックスに`http(s)://`で始まるURLを入力してEnterを押すと、一覧に載っていない記事でも`#/entry?url=...`へ遷移してそのURLのブックマークコメントを表示します(表示は通常の個別記事ページと同じ。一覧に無いURLなので前後の記事ボタンは無効)。個別記事ページからも同様に別のURLへ遷移できます。IME変換確定のEnterでは遷移しません。
- **コメント表示**: 一覧の「ブックマークコメントを見る」から個別記事に遷移すると、`https://b.hatena.ne.jp/entry/jsonlite/?url=...` をJSONPで取得し、そのページをブックマークした各ユーザーのコメント・タグ・日時を表示します。表示形式は「plain」(テキスト中心)と「rich」(ユーザーアイコン・タグ付き)を切り替え可能で、選択状態は`localStorage`に保存されます。
- **コメントのスター数(richのみ)**: 個別記事ページをrichレイアウトで表示している時だけ、はてなスターAPI(`https://s.hatena.ne.jp/entries.json`)で各コメントのスター数を取得し、コメント末尾に「⭐️n」と表示します(0件は何も表示しない。誰が付けたかは扱わず数のみ。通常のスター+色付きスターの合計で、多い場合にAPIが`{count: N}`にまとめた分も加算)。対象はコメント付きで表示中のブックマークのみで、ブックマークのパーマリンク(`https://b.hatena.ne.jp/{user}/{yyyymmdd}#bookmark-{eid}`)をURIとして50件ずつまとめて問い合わせるため、リクエストは**記事を1回開くごとに ceil(コメント数/50) 本**(ほとんどの記事は1本、並列実行、10秒タイムアウト)。取得は記事ごとに1回だけで、plain→richに切り替えた時に初めて走り、plainのままなら一切通信しません。失敗しても黙って無視し、コメント表示には影響しません。単数形の`entry.json`はCORSヘッダが無く、`callback`によるJSONPも効かないため使えません(`entries.json`のみCORS対応)。
- **コメント一覧非表示設定の検出**: はてな側で「コメント一覧は非表示に設定されています」になっている記事は、jsonliteが「ブックマーク数はあるのに`bookmarks`が空」で返す(コメントが無いだけの記事では`bookmarks`は空にならない。25記事で実測確認)。この形を検出した場合は「コメントはありません。」ではなく「コメント一覧は非表示に設定されています。」と表示し、その時点でミュートに自動登録して一覧から外します。この設定はブログ/ユーザー単位でかかるため、ユーザー単位だと分かっているホスト(はてなブログ系のサブドメイン、`zenn.dev/{ユーザー}/`)は`urlprefix`(URL前方一致)でまとめて登録し、それ以外のホストはホスト全体を巻き込まないよう従来どおりその記事のURL(url)のみ登録します(許可リストは`js/filters.js`の`scopeRuleForUrl`。コード内の初期値に加え、フィルタ用Gistに`tycoon-scope-hosts.csv`(`mode,host`。`mode`は`path`=`zenn.dev`型 / `subdomain`=`hatenablog.com`型)を置くとホストを追加できる(「Gistを作成」時に`path,zenn.dev` / `path,note.com` / `subdomain,hatenablog.com`の初期内容で自動作成する)。Gist側を直接編集する取り込み専用で、起動時と「保存して同期」で取り込んでlocalStorageにキャッシュし、書き戻さない。不正な行は無視)。同じ判定は、一覧・個別記事ページのドメインボタンを押してミュート設定を開く時にも使い、該当ホストはドメイン全体ではなくユーザー単位の`urlprefix`が入力済みで開く(Gist同期は積み上げ方式のため、他端末にも広がり、削除は同期されません)。
- **未ブックマークのURL**: まだ誰もブックマークしていないURLは、jsonliteがエラーではなく`null`を返す。コメント内のリンク化やURL直接入力で普通に起こるため、例外にせず「このURLはまだ誰もブックマークしていません」と元記事へのリンクだけを表示する(既読記録・オフライン用キャッシュ保存の対象外)。以前は`normalizeEntryInfo`が`null`の`raw.url`を読んで「null is not an object (evaluating 'raw.url')」になっていた。
- **コメント中のURLのリンク化**: コメント本文に含まれる`http(s)://`のURLは、hateb-tycoonの個別記事ページ(`#/entry?url=...`)へのリンクになります(plain/rich共通、同じタブで遷移)。URL以外の部分は従来どおりエスケープして出力します。URL末尾の句読点・括弧は含めず(「(https://example.com)」のように括弧で囲まれていても巻き込みません。`Foo_(bar)`のようにURL内で括弧が対になっている場合は含めます)、長いURLがスマホ幅ではみ出さないよう折り返します。
- **既読管理**: 一度開いた記事は視覚的に既読(輝度低下)として扱われます。ブックマーク数が既読時から一定以上増えた場合(設定で割合/件数を指定可能)は、グレーアウトを外して未読同様に目立たせつつ、「更新」バッジを付けて、既読済みでブックマーク数が増えたことを示します(未訪問の未読とは見分けが付きます)。文言は当初「既読」でしたが、バッジとして強調されていると意味が分かりにくかったため「更新」に変えました(本当は「更新あり」が分かりやすいが、スペースの都合で「更新」)。バッジの位置は、richでは「更新 yyyy-MM-dd」(はてなの更新日時)の左です。plainではタイトルの左に置くと開始位置がずれて実機で使いにくかったため、行の流れの外に出し(横幅も改行も増えず、タイトルの開始位置が揃う)、行の左端のアクセント線(Scrapboxのテロメア風)だけで示します(未読・既読の行も同じ3pxを透明で確保し、見た目の位置を揃えています)(左上角に「更新」タブも付けてみましたが、スマホ幅でごちゃついたため線のみにしました)。plainでは、タイトルと「N users →」を合わせた範囲全体がブックマークページへのリンクになります(元記事へはカード/行内のタイトルをTab操作で、またはブックマークページ内のタイトルから開けます)。「既読なら非表示」トグルで一覧から隠れるのは、更新の無い既読記事のみです(このバッジ付きの記事は隠れません)。
- **新着コメント表示**: 個別記事ページを開くと、前回そのページを開いた時刻より後に付いたコメントに「NEW」バッジを付け(一覧の「更新」と同様、グレーアウトはしません)、前回訪問時点で既にあったコメントはグレーアウトし、ステータス行に新着件数を表示します(plain/rich共通)。判定はコメントのtimestamp(JST、分単位)と`visited`に記録済みの前回訪問時刻の比較のみで、コメント一覧自体は保存しません。timestampが分単位のため、前回訪問と同じ分のコメントは新着側に倒します。初訪問の記事は比較対象が無いためバッジは付きません。開いた時点で訪問時刻が更新されるため、同じ記事を続けて開き直すとバッジは消えます。
- **キーボード操作**: 一覧ページで矢印キーを押すと最初の未読記事へジャンプ、個別記事ページでは前後の記事へ移動します。移動先は「既読かつ更新なし」の記事を読み飛ばして決め(先読みの対象も同じ)、その判定は一覧から記事ページに入った直後の既読状態(スナップショット)を一覧に戻るまで使い回します(毎回判定し直すと、見てきたばかりの記事まで「前の記事へ」で飛ばしてしまうため。滞在中に隣の記事が更新された場合は考慮しません)。ただしこのセッション中に既に開いた記事は、元が既読でも飛ばしません(ページ下部の「前の記事へ」「次の記事へ」ボタンでも同様の操作が可能。スマホでの片手操作を想定した全幅ボタンです)。
- **既読の同期(Gist)**: 設定モーダルの「既読の同期」で、既読をシークレットGist(`hateb-tycoon-visited.json`)経由で端末間共有できます(既読のみ。フィルタ設定は対象外)。`localStorage`が常に正で、既読の記録・判定はGistに触れません。通信は起動時/タブ復帰時(前回から5分以上)の読み込み(ETagで304なら実質ゼロコスト)と、既読が増えた45秒後(またはタブを隠す時)のまとめ書き込みのみです。書き込みにはclassic PATの`gist`スコープが必要(fine-grained PATはGist非対応)で、トークン未設定の端末は読み取り専用になります。トークンは既読の同期とフィルタの同期で共通の専用入力欄(「GitHubトークン(Gist用)」)から設定し、端末の`localStorage`に保存されます(旧仕様で既読同期の設定に入っていたトークンは自動で引き継ぎ)。Gist IDの隣の「↗」で`https://gist.github.com/<id>`を開けます(ユーザー名なしのIDだけでも所有者のGistページへリダイレクトされます)。マージはURLごとに`time`の新しい方を採用します。
- **ミュート機能**: 右上の「フィルタ設定」から、以下3種類のワードリストを追加・削除できます。ワードは `localStorage` に保存され、ブラウザを閉じても保持されます。
  - `mute`(ミュートワード): 該当したら非表示。ただし `unmute` に該当すれば例外的に表示。
  - `unmute`(ミュート解除ワード): `mute` の例外として表示を維持する。
  - `forceMute`(強制ミュートワード): 該当したら `unmute` の設定に関係なく必ず非表示。
  - 各ワードは「タイトル」「ドメイン」「はてなユーザー」「ブックマークコメント」「URL」のいずれかを対象に判定します。URL以外は部分一致(大文字小文字を区別しない)、**URLのみ完全一致**です(記事カードの「×」ボタンで、その1記事だけをピンポイントでミュートする用途のため)。一覧表示のデータには個々のブックマークユーザー・コメント情報が含まれないため、「はてなユーザー」「ブックマークコメント」によるミュートは個別記事のコメント表示(jsonlite由来)でのみ有効です。
  - フィルタ設定はCSV(`type,value`)でエクスポート/インポート可能です(ファイルダウンロード・クリップボードコピー・画面上へのテキスト表示の3通り。インポートはCSVファイル選択)。
    - **フィルタのGist同期**: 既読の同期と同じ仕様で、Gist IDだけを設定します(トークンは共通)。ミュート・ミュート解除・強制ミュートの**3種をまとめて1つのシークレットGist**に、種類ごとのCSV(`tycoon-filter-<mute|unmute|forceMute>.csv`(feed-tycoonと共有するためアプリ名は含めない))として保存します。「Gistを作成」でGistとファイルを自動作成し、「保存して同期」は「Gistから取り込み(マージ)→ローカルとの和集合でGistを上書き」です。つまりルールは**積み上げ方式**で、削除は同期されません。消したい場合はGist側のCSVを直接編集します(他端末のローカルに残っていれば次の同期で復活します)。トークン未設定の端末は取り込みのみ(読み取り専用)です。
      - リモートのCSVが1行でも不正(値が空など)な種類は、取り込まず、ローカルの内容での上書きもしません(手編集の途中で壊したCSVを消さないため)。その旨は取り込み結果に表示されます。ヘッダーのみ・空のファイルは「ルール無し」として扱います。
      - [feed-tycoon](https://github.com/gosyujin/feed-tycoon)と同じGist・同じファイルを共有できます。hateb-tycoonが持たない`type`(`source`/`tag`/`description`等)の行は取り込み時にエラーにせず無視し(結果に「未対応の種別N件は無視」と表示)、上書き時にはリモートの行をそのまま残します(feed-tycoonのルールを消さないため)。`type`が空・`value`が空・列数不正の行はエラーです。
    - **起動時の自動取り込み**: Gist IDを設定済みなら、アプリ起動時に最初の描画前にGistから取り込みます(書き込みはしません。ETagで変更なしなら304)。オフライン等で遅い場合に起動を待たせないよう、待つのは最大3秒で、失敗は無視して通常起動します。
    - 旧仕様の「インポート用URL」(Gist rawURLを種類ごとに登録)は廃止しました。
- **オフライン対応(機内モード等)**: Service Workerによりアプリ本体と全カテゴリーの一覧データを事前キャッシュし、電波が無い状態でも一覧・既読管理・フィルタ設定は利用可能です。詳細は[architecture.md](architecture.md)の「オフライン対応の仕組み」を参照してください。

## 判定ロジック(ミュートワード、優先順位)

```
1. forceMute に一致する -> 非表示(確定)
2. mute に一致する
     -> unmute にも一致する -> 表示
     -> unmute に一致しない -> 非表示
3. どちらにも一致しない -> 表示
```

## 機能の挙動(旧README「技術的な注意点」より)

- **一覧の自動リフレッシュ**: 一覧データは静的JSONでサーバーからpushできないため、feed-tycoonと同じく「ページが前面に戻った時(`visibilitychange`)に、最後の読み込みから5分以上経っていれば読み直す」方式にしています(`refreshListIfStale()`)。通常の読み込み(`renderListView`)は一覧を一度空にしますが、自動リフレッシュは**取得に成功し、かつ内容が変わっていた場合のみ**差し替え、スクロール位置も維持します。オフライン復帰などで取得に失敗しても表示中の一覧は消えません。
- **自動スクロール**: ヘッダーの▶️/⏸️でON/OFF。状態は`localStorage`(`hateb-tycoon:autoScroll`)に保存し、一覧⇔記事・前後の記事へ移動してもONのまま続く。`requestAnimationFrame`で`window`を設定画面で変えられる速度(既定毎秒20px、`hateb-tycoon:autoScrollSpeed`)で下へ送るだけで、wheel/touch/keydownの直後1.5秒は一時停止して手動操作を邪魔しない。設定画面を開いている間も一時停止し(状態は変えず、閉じれば再開)。

## フィルタのGist同期 詳細仕様(旧 docs/gist-sync-spec.md)


hateb-tycoon コミット `ac1f206` で導入した仕様。feed-tycoon も同じ方式へ移行するための引き継ぎ資料。
実装の正本は hateb-tycoon の `js/gist.js` / `js/filter-sync.js` / `js/app.js`(「フィルタの同期」節)。

### 1. 概要

- フィルタルール(hateb-tycoonは mute / unmute / forceMute の3種)を、**シークレットGist**経由で端末間共有する。
- 設定するのは **Gist ID だけ**(GistのURLを貼ってもIDを抽出する)。ルールの保存形式は従来どおりCSV(`type,value`)。
- 既読の同期(hateb-tycoon `js/sync.js`)と同じ操作感・同じトークン。
- **旧仕様(種類ごとにGist rawURLを登録して取り込む)は廃止**。移行処理は入れていない。

### 2. Gistの構成

- 1つのGistに、ルールの「種類(kind)」ごとに1ファイル。ファイル名は `tycoon-filter-<kind>.csv`(**アプリ名を含めない**。プロジェクト間で同じGist・同じファイルを共有する)
  - `tycoon-filter-mute.csv` / `tycoon-filter-unmute.csv` / `tycoon-filter-forceMute.csv`
  - feed-tycoon も**同じファイル名**を使う。kindはhateb-tycoonと同じ3種(mute/unmute/forceMute)を前提とする(feed-tycoon側に他のkindがあれば別途協議)。
- CSV形式: 1行目ヘッダー `type,value`、改行 `\r\n`、`,` `"` 改行を含む値は `"` で囲み `""` でエスケープ。出力は `type asc, value asc` ソート済み。
- 説明(description): `hateb-tycoon filters`。`public: false`(シークレット)。

#### type の扱い(feed-tycoon固有の注意)
- 取り込み時、自アプリが扱わない type の行はエラーにせず無視して件数を数える(結果に「未対応の種別N件は無視」)。
  hateb-tycoon が扱うのは `title`/`domain`/`user`/`comment`/`url`。feed-tycoon は加えて `source`/`tag`/`description` も扱うので、それらは取り込む(逆に feed-tycoon が扱わない type があれば無視)。
- **ファイルを共有するため、上書き時は「リモートCSVにあった未対応typeの行」をそのまま残して書き出す**(相手アプリのルールを消さない)。実装: パーサーが無視した行を `ignoredRules` として返し、push時にローカルルールと合わせてソートして出力する。**feed-tycoon側でも必ず同じ保持処理を入れること**(入れないと hateb-tycoon 専用type の行を上書きで消す)。

### 3. トークン(両同期で共通)

- classic PAT の `gist` スコープ(fine-grained PATはGist非対応)。
- **独立した入力欄**「GitHubトークン(Gist用)」に分離。既読同期・フィルタ同期の両方がこれを使う。
- 保存先: `localStorage['hateb-tycoon:gistToken']`(feed-tycoonは自アプリのキー名にする)。
  - 入力欄の `change` イベントで保存。各「保存して同期」「Gistを作成」ボタンでも押下時に最新値を保存してから処理する。
  - 旧仕様で既読同期の設定(`hateb-tycoon:sync`)内に同居していたトークンは、新キーが未設定の時のみ自動で引き継ぐ(空文字を保存済みなら再移行しない)。
- **読み取りにトークンは不要**(シークレットGistはIDを知っていれば読める)。トークン空の端末は読み取り専用。

### 4. UI

インポート・エクスポート設定セクションの下部に「フィルタの同期(Gist・全種まとめて)」:

1. Gist ID 入力欄(placeholder「Gist ID または URL」)+ 「↗」リンク
2. ボタン: 「保存して同期」「Gistを作成」
3. ステータス行(`filter-sync-status`): 未設定 / 「読み書き|読み取り専用 / 最終同期 <日時> [/ エラー: …]」
4. 結果詳細は既存のインポート結果欄(`import-status`)に表示

- 「↗」: `https://gist.github.com/<ID>`(**アカウント名不要**。IDだけで持ち主のGistページへリダイレクトされる)。IDが空なら非表示。入力欄の `input` イベントでも更新。既読同期側にも同じ「↗」を付けた。
- 種類タブ(「対象: ミュート」)とは**連動しない**。同期は全種まとめて。CSVコピー/エクスポート/ファイルインポートは従来どおり選択中の種類のみ。
- 旧「Gistから取得」URLフォームと「↗」(rawURL用)は削除。

### 5. 動作仕様

#### 「Gistを作成」
1. Gist IDをクリアして設定 → 全kindのローカルCSV(ヘッダーのみでも可)で `POST /gists`(トークン必須、無ければ「先にトークンを入力してください」)。
2. 返ったIDを保存 → 続けて「保存して同期」と同じ処理を実行。

#### 「保存して同期」(`FilterSync.sync`)
1. 入力欄のIDを保存(ETagはクリア)。ID空ならエラー「Gist IDを入力してください」。
2. `GET /gists/<id>`(ETagなしで全量取得)。
3. 各kindについて、リモートCSVを **取り込み(マージ)**:
   - ファイル無し/空/ヘッダーのみ(`type,value`だけ)→ 「リモートにルール無し」(スキップ。※パーサーは空データをエラーにするので先に除外する)
   - 解析エラーが1行でもある → **その種類は取り込まず、上書きもしない**(手編集途中の壊れたCSVをローカルで潰さないため)。エラーは結果に表示。
   - それ以外 → 既存ルールと重複(`type` + `value` の大文字小文字無視一致)しない分だけ追加(`Filters.importRules`)。
4. トークンがあれば **上書き(push)**: 不正CSVでない各kindについて、ローカルルール(ソート済みCSV)とリモートCSVを改行正規化・trimして比較し、**差分のあるファイルだけ** `PATCH /gists/<id>` で更新。
   - ローカル0件かつリモートファイル無し/空のkindは作らない。
   - 差分が無ければPATCHしない。書き込んだ場合はETagをクリア(自分の書き込みでETagが変わるため)。
5. 最終同期時刻を保存。結果表示: 「N件を取り込み、Gistへ Nファイルを書き込み|トークン未設定のため書き込みなし、未対応の種別N件は無視 / 不正なCSVは取り込まず上書きもしていません(kind: エラー…)」
6. 取り込み後はルール一覧と一覧画面を再描画。失敗時は `lastError` を保存して「失敗: <理由>」。

**積み上げ方式**: 同期 = リモートとローカルの和集合。**削除は同期されない**。消したい時はGist側のCSVを直接編集する(ただし他端末のローカルに残っていれば次の同期で復活する)。

#### 起動時(`FilterSync.syncOnStartup`)
- Gist ID設定済みなら、最初の描画前に **取り込みのみ**(書き込みなし)。
- 保存済みETagで `If-None-Match` 付きGET。304なら何もしない(レート制限にも数えられない)。200なら上記マージを実行しETagを保存。
- 待つのは最大3秒(`STARTUP_IMPORT_TIMEOUT_MS`)。失敗・タイムアウトは無視して通常起動(`lastError`は保存、コンソールにwarn)。
- 既読同期の起動時pullと並列実行(`Promise.all`)してから初回描画。

#### エラー文言(`Gist.describeHttpError`)
401 トークンが無効です(失効の可能性) / 403 アクセス拒否またはレート制限です / 404 Gistが見つかりません(IDまたはトークンの権限を確認) / その他 `HTTP <status>`

### 6. モジュール構成(hateb-tycoon)

| ファイル | 役割 |
|---|---|
| `js/gist.js`(新規) | `Gist`: トークン get/set(旧設定からの移行込み)、`parseGistId`、`pageUrl`、`get(id, etag)`(304→null)、`fileText`(truncated時はraw_url取得)、`update`(PATCH)、`create`(POST, public:false)、`describeHttpError` |
| `js/filter-sync.js`(新規) | `FilterSync`: `init({parseCsv,toCsv})`、`sync`、`syncOnStartup`、`createGist`、`configure`、`getConfig`。状態は `localStorage['hateb-tycoon:filterSync']` = `{gistId, etag, lastSyncAt, lastError}` |
| `js/sync.js`(改修) | 既読同期。トークンを `Gist` 共通管理へ移し、API呼び出しも `Gist` 経由に |
| `js/app.js` | CSV解析/生成(`parseImportCsv`/`rulesToCsv`)を `FilterSync.init` に注入、UI配線、起動時同期 |
| `index.html` / `css/style.css` | トークン欄・同期欄のUI、`.gist-row` スタイル |
| `service-worker.js` | `SHELL_FILES` に `js/gist.js` `js/filter-sync.js` を追加(**忘れるとオフライン起動で読み込めない**) |

スクリプト読み込み順: `filters.js` → `visited.js` → `gist.js` → `sync.js` → `filter-sync.js` → … → `app.js`。
