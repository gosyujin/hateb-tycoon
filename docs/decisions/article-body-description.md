# 記事本文の抜粋でdescriptionを差し替える

## 背景

一覧データ(`data/hotentry-*.json`)の`description`は、はてなのRSSが返す概要で、平均150字ほどしかなく、空のものもある(「全て」1965件中82件。実際に新しい側40件を取った時は、元が空だった記事が大半だった)。ストリーム表示や「コメント」フィルタの判定は`description`を使うため、情報量を増やしたい。そこで、記事のページから本文の抜粋を取り、`description`を差し替える。

## 判断

- **取得場所はGitHub Actions(`scripts/fetch_hotentry.py`)。** ブラウザからは記事サイトのCORSで取れない。既存の中継Workerは任意URLを取りに行く入り口になるため使わない。
- **抽出は標準ライブラリのみ**(`scripts/article_body.py`、`html.parser`)。まず簡易抽出で始め、物足りなければ`trafilatura`等の導入を検討する(その時は`pip install`が要り、「追加パッケージ不要」の方針を変えることになる)。抽出は、`<article>`/`<main>`の中(無ければページ全体)の文字の塊のうち40字以上のものを順に集め、定型文(ログイン・Cookie・©等)を含む短い塊と、`<nav>``<header>``<footer>``<aside>`などの中を捨てる。本文が取れなければ`<meta>`の`og:description`/`description`。本文の頭に重なっているタイトルは除く。
- **抜粋は300字**(`MAX_BODY_CHARS`)。RSSの`description`の約2倍で、情報量が増え、データの膨張も抑えられる。足りなければこの定数を上げる(データ量は文字数にほぼ比例して増え、Service Workerが全JSONを先読みする)。
- **差し替えるのは`description`そのもの**(別フィールドにしない)。元のRSSの値は残さない。`descriptionSource: "body"`で差し替え済みを示し、次回以降のRSSの値で上書きしない(`merge_entries`)。差し替え後の`description`が元より長くならない場合は差し替えない。
- **ミュート判定にも本文を使う**。`js/filters.js`は`description`を「コメント」フィルタの対象にしているので、本文に差し替えると、本文に当たる語でも記事が消える。

## 迷惑をかけないための決まり(変更時は必ず守る)

- robots.txtを毎回確認する(ホスト単位でキャッシュ)。401/403は全面禁止、404などは許可、5xx・通信失敗は今回は見送る。`Crawl-delay`は守り、30秒を超えるホストは見送る。
- リダイレクトは自動で追わず、1ホップごとに転送先のrobots.txtを確認する(最大3回)。
- 名乗るUser-Agent(`hateb-tycoon-bot/1.0 (+リポジトリURL)`)を使う。
- 全体を直列で行い、同じホストへは3秒以上空ける。429/503を返したホストは、その実行中は叩かない。
- 1回の実行で最大40件・240秒まで(`MAX_BODY_FETCH_PER_RUN`/`BODY_TIME_BUDGET_SEC`)。溜まっている分は新しい記事から順に消化する(初回の約2000件は数十回の実行に分かれる)。RSS・コミットを遅らせないよう、本文の取得はデータ更新の最後にまとめて行い、失敗してもRSSのdescriptionのまま更新を続ける。
- HTML以外・600KBを超える応答は読まない。`<meta name="robots" content="nosnippet">`と`X-Robots-Tag: noindex/nosnippet`のページは使わない。
- 保存するのは抜粋(300字)だけで、全文は保存しない(公開リポジトリ・公開サイトに載るため)。
- 同じURLは取得済み(`descriptionSource`)・恒久的な失敗(`bodyStatus: "skip"`)なら二度と取りに行かない。通信の都合の失敗(`retry`)は`bodyTries`で数え、3回で諦める。

## 確認したこと

- 抽出(`<article>`・`<div>`のみ・JS描画・nosnippet・EUC-JP・`<head>`の閉じ忘れ・タイトルの重複)と、取得の作法(robots.txtのdisallow・Crawl-delay・404/500/503・リダイレクトと無限ループ・非HTML・ホスト単位のrobots.txtキャッシュ)を、ローカルのサーバーで確認した。
- 実サイトで40件を取得し、40件とも取得できた(本文37件・`<meta>`3件。うち36件が元より長く差し替え、4件は元のまま)。所要約2分。差し替え後の平均は約293字、元は約40字(空が多い)。
- 未確認: GitHub Actionsのランナーから実際に動かした時の挙動(ボット対策で弾かれるサイトの割合など)、1回の実行で40件を超えて溜まった分の消化にかかる日数。
